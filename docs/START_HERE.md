# С чего начать

## Цель MVP

Пользователь создаёт предмет, загружает запись занятия, получает расшифровку и конспект, может их исправить и позднее найти.

На первом этапе поддерживаем загрузку аудиофайла. Запись через микрофон, отдельное устройство, синхронизацию и аккаунты оставляем на потом.

## Разделение работы

### Арсений — приложение и хранение

- Предложить и выбрать стек приложения.
- Сделать библиотеку предметов и конспектов.
- Реализовать экран добавления аудио и экран результата.
- Хранить аудио, расшифровку, конспект и статус обработки.
- Добавить редактирование, поиск и удаление.

### Участник 2 — аудио и ИИ

- Сравнить распознавание русской речи на одной и той же подборке записей.
- Измерить качество, время обработки и ориентировочную стоимость.
- Реализовать конвейер: аудиофайл → расшифровка → конспект.
- Учесть длинные файлы, ошибки и повторный запуск.
- Сформировать структурированный результат и сохранить ссылку на источник.

## Контракт данных для согласования

Перед параллельной разработкой зафиксируйте поля сущности `Lesson`:

```text
id
subject_id
title
recorded_at
audio_path
transcript
notes
status: queued | processing | completed | failed
error_message
created_at
updated_at
```

Поля и названия можно подстроить под выбранный стек; важно договориться до реализации интеграции. ИИ-модуль должен выдавать предсказуемую структуру конспекта, а не произвольный формат.

## Backlog первой недели

1. **Оба:** выбрать 3–5 тестовых записей разных условий и убедиться, что на обработку есть разрешение.
2. **Участник 2:** сравнить минимум два доступных варианта распознавания на одинаковых фрагментах; записать ошибки терминов, время и стоимость.
3. **Арсений:** набросать три экрана: список предметов, записи предмета, просмотр/редактирование конспекта.
4. **Оба:** согласовать формат `Lesson`, статусы, поддерживаемые типы и максимальную длину записи для MVP.
5. **Оба:** выбрать стек и нарезать backlog на небольшие задачи GitHub.

## Предлагаемые labels

- `app` — интерфейс и приложение
- `ai-pipeline` — распознавание и генерация
- `storage` — файлы и база данных
- `research` — сравнение сервисов и проверка гипотез
- `bug` — ошибка
- `decision-needed` — требуется общее решение

## Правила работы

- Работать в отдельных ветках: `feat/...`, `fix/...`, `research/...`.
- Изменения вливать через Pull Request после просмотра напарником.
- Не коммитить `.env`, ключи API и реальные аудиозаписи.
- Для каждой задачи писать ожидаемый результат и критерий готовности.
- Фиксировать решения по стеку, формату данных и провайдеру обработки в коротких заметках `docs/decisions/`.
